## Release Positioning

This release candidate presents LSC as a constrained phenomenological validation framework. It is not a discovery announcement and does not claim confirmed new physics, sterile-neutrino exclusion, or validated BEST-2 outcomes.

## STEP 1 Summary: Canonicalization

STEP 1 separated the active pre-BEST-2 LSC core from deprecated, historical, speculative, and weakly defined material. It produced:

- active canonical core;
- deprecated component registry;
- historical lineage from LSC 4.x through LSC 6.3.0;
- active equation set classification;
- freeze boundary defining allowed and prohibited claims.

Canonicalization decisions preserve only constrained framework elements intended to remain active during the BEST-2 freeze era.

## STEP 2 Summary: Validation Infrastructure

STEP 2 specified the validation infrastructure required before any strong claim:

- M0-M6 model hierarchy;
- M4 detector/systematics competitor baseline;
- covariance and missing-data policy;
- external veto checklist;
- preregistration policy;
- failure modes and risk matrix.

The STEP 2 conclusion is that validation is possible only as a disciplined comparison framework until covariance-grade data and metadata are available.

## STEP 3 Summary: Implementation and Archival Engineering

All placeholder structures are marked non-validation-grade.

## Freeze Rationale

The freeze exists to protect falsifiability and prevent post-hoc framework drift before BEST-2-era analysis. It preserves a reviewable state that external models and human reviewers can audit without requiring full repository context.

## Remaining Blockers

- Missing covariance-grade datasets.
- Missing extraction-level and orientation/timestamp metadata.
- Incomplete detector/systematics calibration data.
- External-veto mappings not yet performed.
- No completed global likelihood comparison across M0-M6.
- Human review still required for claim language and release metadata.

## Future Data Requirements

Publication-grade validation requires:

- experiment-level covariance matrices;
- extraction-level counts and uncertainties;
- source calibration and activity histories;
- detector orientation/timing/exposure metadata;
- standard oscillation, KATRIN, IceCube, SME/Lorentz, and solar-neutrino constraint mappings.

## Reproducibility Notes

This release candidate includes checksum generation and source/provenance manifesting. Reproducibility still depends on external datasets that are not fully available in machine-readable form.

## Audit Integration Notes

External audits from Claude, Gemini, DeepSeek, Kimi, and reconnaissance material are included as constraint layers. Hostile or critical conclusions are preserved as validation requirements and risk controls, not treated as theory extensions.
